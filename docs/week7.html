Cluster API — 클러스터를 CRD로

클러스터 생성·확장·업그레이드를 선언적으로 (VKS 실무 사례)
개념

Management ↔ Workload

  • Management Cluster — CAPI 컨트롤러가 도는 관리 클러스터
  • Workload Cluster — Cluster/Machine CRD로 생성·관리되는 대상
  • 클러스터가 하나의 K8s 오브젝트가 됨
실무 · VKS

vSphere Kubernetes Service

  • Supervisor = Management, CAPI/CAPV로 클러스터 프로비저닝
  • kubectl get crd | grep cluster.x-k8s.io
  • ClusterClass로 표준화·업그레이드 자동화

패키지 관리 — Helm vs Carvel

선언적으로 앱을 묶어 배포·업그레이드·롤백
Helm 3

Chart · Release

  • Go 템플릿 + values.yaml 오버라이드
  • install / upgrade / rollback / history
  • Release 단위 관리 · 방대한 차트 생태계
Carvel

ytt · kbld · kapp · imgpkg · vendir

  • ytt overlay(템플릿 대신 패치) · kbld 이미지 고정
  • kapp — state-aware diff로 안전 배포
  • App CR(GroupedRecord)로 리소스 묶음 추적

라이브 실습 — CRD · Helm · kapp

확장부터 패키징까지
# CRD + CR 생성, Operator 활용 $ kubectl apply -f crd.yaml && kubectl get backups $ kubectl get crd | grep monitoring.coreos.com # Prometheus Operator # Helm — Chart 만들고 배포·업그레이드·롤백 $ helm create mychart $ helm install demo ./mychart -n demo --create-namespace $ helm upgrade demo ./mychart --set replicaCount=3 $ helm rollback demo 1 -n demo # Carvel/kapp — 매니페스트 묶음을 state-aware 배포 $ kapp deploy -a my-app -f manifests/

과제 — 확장 & 패키징

직접 만들고 비교
CRD/Operator

확장

  • 본인 CRD(예: WebApp) 스키마 + validation 작성
  • Cert-Manager 설치 → Issuer/Certificate 동작 분석
  • Operator vs Helm 5가지 비교 표
패키징

Helm & Carvel

  • Nginx+Service+ConfigMap Helm Chart 직접 작성 → 환경별 values 분리(dev/prod)
  • 동일 워크로드를 Carvel(kapp+ytt)로 재구성 → 차이 비교 보고서

선언적 모델 — 명령이 아니라 선언

K8s의 심장은 "원하는 상태(Desired State)"를 향한 끊임없는 조율
명령형 (X)

Imperative

  • "컨테이너를 지금 실행해"
  • 한 번의 동작, 상태 추적 없음
  • 죽으면 사람이 다시 살려야 함
  • → 규모가 커지면 관리 불가
선언형 (O)

Declarative

  • "Pod가 항상 3개 있어야 해"
  • 원하는 상태를 etcd에 기록
  • Controller가 현재≠원하는 상태면 자동 복구
  • → Self-Healing의 기반

공항으로 이해하는 Control Plane

각 컴포넌트를 공항 역할에 비유하면 직관적이다
  • kube-apiserver — 공항 안내 데스크: 모든 문의·요청이 반드시 거치는 창구
  • etcd — 운항 기록부: 클러스터의 모든 상태가 기록되는 유일한 원장
  • kube-scheduler — 게이트 배정 담당자: 새 Pod를 어떤 노드(게이트)에 붙일지 결정
  • controller-manager — 각 부서 관리자: 예정↔실제를 계속 비교하며 어긋나면 바로잡음
  • cloud-controller-manager — 외부 연결 담당: 클라우드 LB·스토리지 등 외부 서비스 연동

라이브 실습 — 클러스터 구축 & 검증

kubeadm으로 직접 만들고 상태를 확인한다
# 실습 1: 클러스터 자동 설치 (1 Master + 2 Worker) $ chmod +x k8s-install.sh && ./k8s-install.sh # CNI: Antrea/Calico 선택 # 실습 2: 클러스터 상태 검증 $ kubectl get nodes -o wide $ kubectl get pods -n kube-system $ kubectl cluster-info # 실습 3: Control Plane을 Static Pod로 직접 확인 $ ls /etc/kubernetes/manifests/ $ sudo crictl ps | grep -E 'apiserver|etcd|scheduler|controller'

학습 목표

"서비스를 어떻게 노출하고 연결하나"
  • Pod 네트워크 모델 — 모든 Pod가 하나의 평면 IP로 통신하는 원리를 이해한다
  • Service 4타입 — ClusterIP / NodePort / LoadBalancer / ExternalName을 구분한다
  • kube-proxy — iptables / IPVS 모드 동작을 안다
  • Ingress — 도메인·경로 기반 HTTP 라우팅을 구현한다
  • CNI — Antrea / Calico / Cilium의 역할·차이를 설명한다

Service 4가지 타입

사라지는 Pod IP 앞에 안정적인 연결점을 제공
타입노출 범위용도
ClusterIP클러스터 내부 (기본)내부 서비스 간 통신 · 가상 IP
NodePort노드 IP:30000–32767외부에서 노드 포트로 접근 (개발/테스트)
LoadBalancer외부 LB VIP클라우드/MetalLB로 외부 노출
ExternalNameDNS CNAME외부 도메인을 클러스터 이름으로 매핑

CNI 비교 — Antrea · Calico · Cilium

Pod 네트워크·정책을 구현하는 플러그인, 데이터플레인이 다르다
Antrea

OVS 기반

  • Open vSwitch 데이터플레인
  • NetworkPolicy + Antrea CRD
  • VMware/VKS 기본 CNI
Calico

L3 라우팅/BGP

  • BGP 라우팅(터널 없이도)
  • 강력한 NetworkPolicy
  • 대규모·성능 안정
Cilium

eBPF 기반

  • eBPF 데이터플레인·고성능
  • L7 정책·Hubble 관측성
  • kube-proxy 대체 가능

라이브 실습 — Service & Ingress

타입별 차이 관찰 후 Ingress Controller 설치
# 실습 1: Service 타입 비교 (ClusterIP → NodePort → LoadBalancer) $ ./k8s-learn.sh # 4번 메뉴 # 실습 2: Ingress Controller(nginx) 설치 $ helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx $ helm install ingress-nginx ingress-nginx/ingress-nginx \ -n ingress-nginx --create-namespace \ --set controller.service.type=NodePort
